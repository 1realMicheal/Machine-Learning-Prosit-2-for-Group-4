ICS553: Machine Learning Essentials · ProSIT 2 · Ashesi University
Team: Elise · Henry · Nana · Micheal

Project overview
This project studies two related supervised-learning tasks using the provided Kenyan digital-lending records:

Default-risk classification: estimate the probability that a loan will default (target: 0 = repaid, 1 = default).
Historical loan-amount regression: estimate Total_Amount (the amount historically disbursed, in Kenyan shillings, KES).
The project emphasises point-in-time feature engineering, protection against target leakage, severe class imbalance, several validation protocols, error analysis, and a local Streamlit demonstration. The amount prediction is not a validated optimal credit limit, and the classifier is not an automated lending policy.

Research/deployment status: Development-time model comparisons completed; chronological holdout performance deteriorated and must be reported honestly. The deployment UI is a prototype and may require local debugging. The project has not established generalisation from Kenyan loans to Ghanaian applicants. Do not use it for real lending decisions.

Step A — Build V2 features
Open ProSIT2_Feature_Engineering_V2_Train_Only.ipynb.

Configuration in the opening code cell:

TRAIN_PATH = Path('data/raw/train.csv')
ENFORCE_SIX_DIGIT_CUSTOMER_IDS = True
QUARANTINE_REPEATED_LOAN_IDS = True
BUILD_SENSITIVITY_REPAYMENT_FEATURES = True
This notebook audits record identity and duplicate loan IDs; builds customer lifetime summaries for descriptive use only; and produces per-loan, historical borrowing features. The primary F1 contract contains 26 features: eight current/context/calendar predictors, 14 earlier borrowing statistics, and four history-availability indicators.

Primary histories use only loans from strictly earlier calendar dates, excluding same-day loans. Previous repayment outcomes are not used by F1; due-date-derived F2 outcome features are exploratory only because actual outcome-recording times were unavailable.

Expected outputs include:

Identity caveat (important for reproducing our run): During development, some customer IDs did not meet the assumed six-digit formatting rule. The local training run relaxed the format-only assertion and retained IDs as nonempty strings. The original notebook files may still contain strict checks, so an unmodified rerun can stop at invalid_customer_ids.csv or a six-digit assert. If independent source checks confirm that these values genuinely occur in the original train.csv, set ENFORCE_SIX_DIGIT_CUSTOMER_IDS = False in the engineering notebook and consistently change downstream format-only assertions to warnings. Never relax nonempty-ID requirements, ID uniqueness, source-to-engineered identity equality, or the identity_mismatches.csv stop condition. A nonempty identity-mismatch audit is a data-integrity failure, not a harmless formatting difference. If the source actually contains only six-digit IDs, investigate the discrepancy and rebuild rather than merely bypassing it. Document any local code changes in the Git commit used for grading.

The development-selected configurations were Random Forest for default classification (pooled grouped-CV PR-AUC ≈ 0.2355) and log-target HistGradientBoosting for amount regression (pooled grouped-CV MAE ≈ 7,016 KES). The threshold and features are stored in model metadata.

Convergence note: Successful fits and zero recorded failures are not proof of convergence for every numerical optimiser. Inspect warnings and logs. RBF SVC/SVR can be slow or memory-intensive; switching RUN_KERNEL_MODELS=False changes the experiment set and must be reported.

5. Running the interactive Streamlit demo
Copy the contents of NkwaPay_V2_Interactive_Demo.zip into the repository root if they are not yet tracked. Confirm that the three V2 model files listed in Step D exist. Then run:

python -m unittest discover -s tests -v
streamlit run deployment/app_v2.py
The interface offers:

Manual application: customer_id, loan_type, duration, disbursement_date, plus optionally earlier loans (customer_id, past disbursement_date, Total_Amount, duration). The adapter constructs the 26 F1 predictors; the user does not enter these engineered values directly.
CSV/batch scoring: load an original-format application CSV, optionally with a separate historical ledger, or upload a pre-engineered F1 CSV. Historical events must precede the assessed application. Same-day events are excluded from history.
FX display: enter GHS per 1 KES. The displayed regression amount is max(0, predicted_KES) × exchange_rate. The app does not fetch a live currency rate and does not modify the default-risk probability.
For a fictional demonstration, the separately supplied nkwapay_demo_100_applicants.csv (100 applications) and nkwapay_demo_100_applicants_history.csv (203 prior loans) may be used. These files are synthetic and are not model training or evaluation data. They must not be mistaken for a Ghana-labelled validation set.

Known limitation: The demo UI had unresolved integration/runtime errors at submission time; unit tests for the feature adapter do not establish that the end-to-end Streamlit app and all saved model binaries have been successfully tested together. Run the app locally and inspect the traceback if it fails. Avoid claiming production readiness.

6. Evaluation and leakage-control summary
Area	Method and interpretation
Classification target	target (1 = default)
Regression target	Total_Amount in KES
Core predictor set	F1 — 26 application/borrowing-history features
Excluded current outcomes	Current target, current Total_Amount, current repayment amounts, due date as a predictor
Excluded identifiers	customer_id, ID, tbl_loan_id, country_id, lender_id are not fitted predictors; IDs support grouping and auditing
Feature construction	Strictly earlier loans only; no same-day borrowing matches
Grouped evaluation	Customers do not span training and validation within a grouped fold
Imbalance handling	Weighted classifiers, PR-AUC, threshold sweep; no resampling in reported final run
Classification metrics	PR-AUC primary, ROC-AUC, precision, recall, F1, threshold/confusion diagnostics
Regression metrics	MAE primary, RMSE, R², log-scale diagnostics and residual analysis
Final test	Saved later-in-time chronological holdout; not used to select models
Known validity risks	Customer-ID format discrepancy, imperfect decision-time proxies, shift across dates, poor chronological generalisation
Lifetime customer profiles are descriptive only, not predictors for per-loan deployment: aggregating over an entire customer's future would leak information into earlier loans. Likewise, historical defaults are excluded from the selected F1 predictor contract; the exploratory F2 features require stronger outcome-availability evidence before operational use.

8. Responsible use, limitations and team contribution
The model has not been shown to generalise reliably to later loan records or to Ghana. The GHS output is an illustrative currency conversion only.
Predictions may be inaccurate, poorly calibrated, or affected by under-recorded borrowing history. The model should not automatically approve, decline, or set loan limits.
The data does not establish the actual timestamp at which prior loan outcomes became known. Due dates are only imperfect proxies.
Borrower data, model artifacts and raw predictions must be handled carefully. Never load an untrusted .joblib file: joblib.load can execute arbitrary code.
The research and engineering work was collaborative across Elise, Henry, Nana and Micheal, including design decisions, experimentation, interpretation and presentation. Individual contribution statements should reflect each member's actual work.
